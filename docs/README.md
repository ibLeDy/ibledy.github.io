# Project documentation

Documentation is intentionally small and split by lifecycle:

- `current-architecture.md` records only the implementation that exists now.
- `plans/YYYY-MM-DD-topic.md` holds proposed designs, decisions, and migration
  plans until they ship.
- `tasks/` is reserved for durable follow-up notes that would be lost in an issue
  or pull request.

Create plan and task directories when the first document needs them; empty
scaffolding is not required. When a plan ships, update the current architecture
and remove or clearly mark stale follow-ups.
